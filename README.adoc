= FpDebug

link:https://www.gnu.org/licenses/gpl-2.0.html[image:https://img.shields.io/badge/license-GPL2-blue.svg[GNU General Public License, version 2]]

FpDebug  is a heavyweight Valgrind tool for detecting floating-point accuracy problems.

The tool uses MPFR for its side-by-side computation in higher precision.
Because MPFR is run with the tool on top of Valgrind,
it has only access to the partial C library provided by Valgrind.
Thus, a patch for MPFR is provided that adjusts it to run on top of Valgrind.
As GMP is used by MFPR, a patch for GMP is also provided.

== Quick start

The `docker` folder contains Dockfiles for several systems
that can be used to build and play around.
During the build a small example program is also built and
analyzed to check that everything works.

[source,bash]
.Build and run Docker image
----
sudo docker build -t fpdebug .
sudo docker run -it fpdebug /bin/bash
----

== Build from source

NOTE: Only 64bit x86_64 and ARM64 systems are supported.
NOTE: The build uses Valgrind 3.22.0 for modern host compatibility.
NOTE: CI smoke tests run on both x86_64 and ARM64 runners (`.github/workflows/fpdebug-smoke.yml`).

The following installation instructions are for Ubuntu 16.10 (64bit).
The instructions should be similar for most other Linux systems.

[source,bash]
.Install build dependencies
----
# Git is only needed to check out the sources
sudo apt-get install git
# m4 is a dependency of GMP
sudo apt-get install m4
# curl is used by install_valgrind.sh to fetch Valgrind if missing
sudo apt-get install curl
# libc6-dbg is required for Valgrind (otherwise it fails at runtime)
sudo apt-get install libc6-dbg
----

[source,bash]
.Get the sources
----
git clone git@github.com:fbenz/FpDebug.git
----

[source,bash]
.Install patched GMP 5.0.1
----
./install_gmp.sh
----

[source,bash]
.Install patched MPFR 3.0.0
----
./install_mpfr.sh
----

[source,bash]
.Install Valgrind with FpDebug
----
./install_valgrind.sh
----

=== ARM64 migration notes (for maintainers)

Key compatibility points:

* Keep Valgrind at `3.22.0` (older versions are not reliable on modern hosts and miss required APIs/instruction support).
* FpDebug DebugInfo calls must use `DiEpoch` (for example via `VG_(current_DiEpoch)()` in `fd_main.c`).
* Install tool binaries to `$(pkglibexecdir)` (not `$(pkglibdir)`) in `Makefile_template.in`.
* Keep legacy GMP/MPFR builds explicit about target triplet (`--build=aarch64-unknown-linux-gnu` on ARM64).
* For static Valgrind tool linking on ARM64:
** build GMP/MPFR with stack protector disabled (`-fno-stack-protector`);
** disable outline atomics where needed (`-mno-outline-atomics`);
** keep the ARM64 `__getauxval` fallback in `fd_main.c`.
* Keep depfile handling compatible with newer automake behavior (`-include` usage and creating `fpdebug/.deps` before build).
* Use `.github/workflows/fpdebug-smoke.yml` as the baseline regression check (must pass on both `ubuntu-24.04` and `ubuntu-24.04-arm`).

Common ARM64 failure patterns and fixes:

* `configfsf.guess: unable to guess system type` in GMP configure:
  use explicit `--build=aarch64-unknown-linux-gnu`.
* `undefined reference to __stack_chk_guard/__stack_chk_fail` during static link:
  ensure GMP/MPFR are built with `-fno-stack-protector`.
* `undefined reference to __getauxval` from `libgcc.a(lse-init.o)` when linking `fpdebug-arm64-linux`:
  keep `-mno-outline-atomics` and the ARM64 `__getauxval` fallback.
* `failed to start tool 'fpdebug' ... No such file or directory` after install:
  verify tool install path is `libexec/valgrind` (`pkglibexecdir`).

== Running FpDebug

[source,bash]
.Build an example
----
cd valgrind/fpdebug/examples
gcc test_1.c -O0 -g -o test_1.out
(or $ gcc test_1.c -O0 -g -mfpmath=387 -o test_1.out )
----

[source,bash]
.Run FpDebug
----
./valgrind/install/bin/valgrind --tool=fpdebug valgrind/fpdebug/examples/test_1.out
----
